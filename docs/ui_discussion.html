POE2 速搜 · 界面形态讨论

基于 68 分类 / 4747 词缀组的真实数据。三类物品结构差异明显，下面是发现和方案，看完回答最后 3 个问题即可。

一、数据揭示的问题：词缀池不是一种形态

物品原型前缀/后缀规模词缀文本特征来源分布特征筛选交互挑战
装备（武器/护甲/饰品） 前缀 14–27 / 后缀 38–44 规整：「+X 生命上限」「附加 X-Y 火焰伤害」，一屏可浏览 六源齐全（基础/渎灵/合金/斯鲁德/精华/瓦尔） 低 — 现有「卡片列表+T级下拉」直接适用
珠宝 前缀 99 / 后缀 93（钻石） 长文本多、复合词缀多（一词条含 2–3 个效果） 仅 3 源（基础/渎灵/瓦尔），无合金/斯鲁德 中 — 190+ 条必须加搜索框+来源筛选，不能靠滚动
引路石 前缀 26 / 后缀 20 超长复合文本（一词条 3–4 个效果连排） 仅基础+渎灵 中 — 同珠宝，需搜索；T级结构不同（低中高阶已分页）
药剂/遗物/宝库钥匙 前缀 7–12 / 后缀 5–8 短文本、数量少 1–2 源 低 — 列表直接摆开
结论：装备是主战场（形态 A 天然适配）；珠宝/引路石需要「搜索+过滤」增强（形态 B）；药剂等小池子随便放。不需要为每类物品单独设计一套表单——两套形态 + 按类别隐藏不适用的来源色标即可。

二、两种界面形态（同一弹窗内自动切换）

形态 A · 装备类（59 分类）

分类 → 基底 → 词缀卡片 → T级

  • 选大分类（如「双手武器」）→ 基底下拉（40 个基底）
  • 前缀/后缀 tab + 来源色标 chips（六源齐全时显示）
  • 词缀卡片列表，点选展开 T级+数值下限
  • 顶部「物品等级」决定可用 T 级

即已实现的 popup 骨架，覆盖 59/68 分类。

形态 B · 珠宝/引路石（9 分类）

同样布局 + 顶部增强条

  • 词缀列表顶部加关键词搜索框（如输「抗性」立即过滤）
  • 来源 chips 变成可点击过滤器（点「渎灵」只看渎灵词缀）
  • 长文本复合词缀用两行卡片，主效果加粗、次效果灰色小字
  • 珠宝无物等概念 → 隐藏物品等级输入，T级选择照常

复用形态 A 的全部组件，只加 3 个增强。

三、跨分类通用交互（所有形态共享）

已选条件托盘

底部固定条：显示已选词缀数（如「前缀 2 · 后缀 1」），点开展开明细可单独删除；「生成并填入市集」按钮常驻。避免选了 3 个词缀后要滚回原处逐个改。

表单适配声明

你提到「很多物品不是同样的表单」——市集侧的表单差异（武器有 DPS 筛选、护甲有品行、地图有掉率）由 content script 按分类路由不同的填充策略，界面侧不感知；自动填表失败时统一降级为条件清单浮层。

四、需要你拍板的 3 个问题

Q1 · 形态 B 的增强范围

搜索框 + 来源过滤器 + 两行卡片，只给珠宝/引路石，还是全部 68 个分类统一都加？

Q2 · 基底选择的必要性

市集搜词缀时基底可以不选（更宽泛）。基底下拉是必选步骤还是可选步骤？

Q3 · 词缀池里的「瓦尔腐化」词缀

瓦尔词缀占全库 1450 条（最大来源），但国服市集能否搜到腐化附魔待验证。界面上怎么处理？
