# POE2 插件一键数据更新指南（scripts/update_db.js）

> 适用场景：流放2 新版本/新赛季（如 0.5.4 → 0.5.5）词缀池、暗金、天梯变化后，一键重建插件全部离线数据库。

## 快速上手

```bash
node scripts/update_db.js                       # 全流程（约 20-40 分钟）
node scripts/update_db.js --dry-run             # 只打印执行计划，不动数据
node scripts/update_db.js --skip=ninja,e2e      # 跳过指定环节
node scripts/update_db.js --league=runesofaldur # 手动指定 ninja 赛季（默认自动检测）
node scripts/update_db.js --asc="Gemling Legionnaire"  # 只抓指定升华（调试用）
node scripts/update_db.js --delay=800           # poe2db/暗金抓取间隔（默认 600ms）
```

- 赛季自动检测：ninja `index-state` API 取当前赛季（如 Runes of Aldur）；市集赛季从 `poe.game.qq.com/api/trade/data/leagues` 确认。
- 运行前自动备份旧库到 `data/backup/{时间戳}/`，中断可手动恢复。
- 失败中断后，可用 `--skip=已完成的环节` 续跑（skip 可选值：`dict, poe2db, align, ninja, e2e`）。
- 结束后生成 `data/update_report.json`（各步骤结果 + 数据统计 + 人工检查项）。

## 数据源结论（匿名可用，勿重复探测）

| 数据源 | 端点 | 说明 |
|--------|------|------|
| 国服市集 stats API | `https://poe.game.qq.com/api/trade/data/stats` | 匿名 HTTP 200，14 组 ~17700 条，新版本词条先到这 |
| 国服市集 items API | `https://poe.game.qq.com/api/trade/data/items` | 匿名 200，24 组（脚本只取 9 装备组，过滤 heist/sentinel 等 POE1 遗产组） |
| 国服市集赛季 | `https://poe.game.qq.com/api/trade/data/leagues` | 匿名 200（当前 S30赛季） |
| ninja 赛季状态 | `https://poe.ninja/poe2/api/data/index-state` | 匿名 200，取 snapshotName/version |
| ninja 角色 | `https://poe.ninja/poe2/api/builds/{version}/character?...` | 纯 HTTP，无需浏览器 |
| 词缀/基底/暗金 | `https://poe2db.tw/cn/...` | 加 UA + 延迟即可，无强反爬 |
| 英→中 stat 桥 | `https://www.pathofexile.com/api/trade/data/stats` | 加 UA，~2MB JSON |

## 人工维护点（无法匿名自动化）

1. **trade2_stats_flat.json（4754 条）** = 市集 UI 词表（peer），来自**登录态**页面 state，匿名 API 与之语义不同（命名空间几乎不重叠），**脚本不会自动重写**。新版本若市集下拉措辞大面积变化（表现为实填未命中增多 / 对齐率骤降）：登录市集 → 保存页内 state → 重新提取 peer_trade2state_cn.json 并拍平 → 重跑 `--skip=poe2db,ninja,e2e`。
2. **market_dropdown_real.json（496 条下拉快照）**：同上，登录态抓取。
3. **poe2db 新增装备分类**：步骤 2 会检测差集并告警，需人工把新分类加进 `fetch_all.js` 的 `MOD_PAGES`/`BASE_PAGES` 后重跑步骤 2-3。
4. **E2E mock 断言**：数据大版本变化可能导致 mock 页面与实际词条不匹配，按 verify 输出微调 `data/tmp/market_mock.html`。

## 历史版本参考

- 2026-09-17：0.5.5（Runes of Aldur / S30）首次全管线验证（9.1 分钟）。期间修两个编排器 bug：
  1. **E2E 假死**：runE2E 最初用 `spawnSync` 跑 verify——同步阻塞事件循环，内置 8642 服务器无法响应，mock 页 `ERR_CONNECTION_REFUSED`。改异步 `spawn` 后全绿。
  2. **builds_db 中文丢失**：`build_builds_db.js` 普通基底中文名原只查 mods_db（官网过滤后仅 63 条），天梯基底 86% `cn=null`。已改为 **data/base_panels.json 优先（1800+ 条全量）→ mods_db 兜底**，重跑 `build_builds_db.js` 即修复（无需重抓 ninja）。
  3. **skip 续跑陷阱**：备份函数会把 data/ninja 旧产物挪走，`--skip=ninja` 续跑时 build_builds_db 无输入。已修为仅 ninja 步骤执行时才挪；若已踩坑，从 `data/backup/{ts}/ninja/` 拷回即可。
