# 版本更新 v0.6.5 — 物品词缀数据库三层重建（失落的珠宝独立 + 全库 statIds 修正）

## 问题（用户反馈）

1. **失落的蓝玉显示的词条是全部蓝玉的**：选基底「失落的蓝玉」，词缀列表混入蓝玉的独立词缀，甚至看不到失落的蓝玉真正的词缀。
2. **选「效果区域提高 #%」搜不到任何结果**：poe2db 上失落的蓝玉根本没有这条词缀，而插件却让它出现在失落的蓝玉的词缀面板里。

## 根因

- 失落的蓝玉/红玉/翡翠/宝钻在 poe2db 是**独立页面**（Time-Lost_Sapphire 等），词缀池全部是「范围内的小型/核心天赋同时提供…」天赋圈词缀，与普通珠宝的 58 条独立词缀**完全不同**。
- 旧库把「失落的X」硬塞进 普通珠宝 分类共享词缀池 → 词缀池错、搜索组合不存在 → 0 结果。
- 全库词缀组的 statIds 还是老对齐脚本（contains 兜底）的产物，如「效果区域提高 #% → enchant.stat_1646093658」是错的。

## 修复

### ① 失落的珠宝独立分类（poe2db 详情页 1:1）
- 新抓 4 页原始数据：`data/raw/Time_Lost_{Sapphire,Ruby,Emerald,Diamond}.json`（60/53/77/160 条 normal + 渎灵/瓦尔/腐化升级/液化情感）。
- 新增 4 个分类：**珠宝·失落的蓝玉/红珠宝/绿珠宝/钻石珠宝**，词缀池来自各自 poe2db 页面，基底只含「失落的X」。
- 普通珠宝分类移除「失落的X」基底；暗金「抗衡黑暗 失落的宝钻」迁入失落的宝钻分类。
- 「液化情感」（Liquid Emotions 灌注）作为新来源类型入库。

### ② 全库词缀组 statIds 重对齐（三层匹配链）
- 新脚本 `align_affix_groups.js`：市集下拉 496（osm，prio1）→ 市集页状态 peer（prio2）→ trade2 静态（prio3）。
- 只做 精确 + 受控同义词归一，**禁用 contains 兜底**；同义词归一冲突时跳过不猜。
- 结果：osm 3321 + peer-exact 918 + peer-vocab 4；对不上的 841 条如实记录 `data/tmp/align_affix_report.json`（多为官方市集尚无对应文本的新版本词缀，如「变形时伤害提高」「植物技能的伤害提高」，宁缺毋假）。
- 「效果区域提高 #%」现正确指向 `explicit.stat_280731498`。

### ③ 物品统一名称 ↔ 词缀页 1:1 映射表
- 新增 `data/maps/base_name_map.json`（脚本 `build_base_name_map.js`）：市集中文基底名 ↔ poe2db 词缀页 slug/原始/解析文件路径的权威映射，后续加基底按表办理。

## 验证

- E2E 四件套全绿：verify_tabs 34/34 · verify_unique_mods 25/25 · verify_local_redirect 21/21 · verify_wysiwyc 7/7。
- 场景验证：失落的蓝玉 60 条词缀全部为天赋圈词缀；蓝玉分类已不含失落的蓝玉；蓝玉+效果区域提高 #% 的 statIds 正确。

## 使用注意

- 需在 edge://extensions 重新加载扩展（数据 mods_db.json 已更新至 v0.95 结构）。
- 失落的珠宝的部分新词缀（变形时伤害/植物技能/在场范围提高等）官方市集暂无筛选项，插件面板仍展示但标注为不可筛（与暗金不可筛词条同样式）。
