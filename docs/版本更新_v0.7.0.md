# 版本更新 v0.7.0 — 进阶模式：一键跟随 ninja 热门 Build 配词缀

> 2026-09-10 · 进阶模式全量上线（数据抓取 → 词条对齐 → 交互 UI → E2E 验证）

## 这是什么

经典模式要自己懂词缀、自己配词缀组；进阶模式把这事砍成「**点选 → 搜索**」两步：

1. **选职业 → 升华 → 流派**（数据来自 poe.ninja 最新赛季 460 个热门 Build 实测样本）
2. **选装备类型**（武器/头盔/护甲/手套/鞋/项链/戒指/腰带/咒符/药水）
3. **点亮该升华职业最流行的装备**（Top-20，按使用率排序，暗金金色/普通白色）
4. **点亮最热词条 Top-10**（按出现率排序，可填数值范围）
5. 点「填入并搜索」→ 自动填好市集所有条件并发起搜索

经典/进阶模式**一键切换**（面板头部），大小风格一致，模式记忆（localStorage），下次打开自动恢复。

## 核心修复：词条对齐链路（47% → 64%，Top-10 榜 70%）

进阶模式词条要能填进市集，得从「ninja 英文模板」对齐到「市集词缀组」。实测发现三层断点，全修：

| 断点 | 原因 | 修复 |
|---|---|---|
| 伪词条抢占 | 同一文本对应多个 stat_id 时只保留第一个，Pseudo 排前面抢位，而词缀组永远不带伪 id → 最热的「物品稀有度提高」必然对不上 | stat_id **全收集**，explicit > implicit > pseudo 排序，输出 `statIds[]` 数组 |
| 大小写差异 | ninja「Cold damage」vs GGG「Cold Damage」 | 大小写不敏感兜底索引 |
| 模板改写 | ninja「# Life Regeneration per second」vs GGG「Regenerate # Life per second」等 | 别名表 `TPL_ALIASES` + `(Local)` 后缀补全 |

运行时匹配同步升级（`popup.js` `findAdvAffixGroup`）：statIds **数组交集** + **打分选组**（base 来源 > corrupted、前/后缀 > 杂项、单词条组 > 混合组），避免把词条填进错误的混合词缀组。

**对不齐的不再静默丢弃**：提交后面板明确提示「N 条市集暂不支持筛选，已跳过」，不再让用户以为点亮了却没生效。剩余 ~36% 不可筛词条多为 POE2 数据源本身缺失（Deflection、# to Spirit 等），属预期行为。

## 交互细节

- 升华 tab 跟随所选职业过滤（佣兵 → 宝石军团士兵/战术家 2 个，不再显示全部 10 个）
- 装备 chips 点亮反色；暗金点亮自动带出全部固定词条（走经典模式暗金链）
- 普通词条点亮出现数值范围输入行（min/max，留空 = 只筛存在）
- 市集单基底限制：多基底点亮时自动取使用率最高的一个
- goBtn 未选满不解锁，按钮文案随部位变化（「填入戒指并搜索」）
